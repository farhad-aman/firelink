## Findings

### firelink/tui/preview.py:272 — correctness — blocker (CONFIRMED)
**Scenario:** Dashboard open; user runs `firelink https://host/file.iso`. `_run` passes `pending=`/`queue=` and has not called `cmd_add`. `run_preview` sees the lock and returns "queued — watch it in the open firelink window" without calling `queue`. Nothing reaches aria2; exit 0.
**Fix:** When the lock is held and `queue` is set, call `queue([], [])` first and report its result.

### firelink/daemon.py:105 — correctness — blocker (CONFIRMED)
**Scenario:** A daemon answers our secret, args changed (upgrade) and `daemon.pid` is missing. `stop_if_stale` calls `_terminate(0)` → `os.kill(0, SIGTERM)`, which signals firelink's own process group. The stale daemon keeps running.
**Fix:** `_terminate` returns for pid <= 0; `stop_if_stale` asks the daemon to shut down over RPC.

### firelink/ytjob.py:227 — correctness — blocker (CONFIRMED)
**Scenario:** A playlist queued with hard subtitles: three jobs finish in one folder; the first takes whichever `.vtt` `iterdir` gives first, burns it in permanently and deletes it; the owner's burn then fails. With no matching track, an unrelated `Movie.srt` is burned in and deleted.
**Fix:** Only accept subtitle files named after the video (`<video stem>.`).

### firelink/tui/app.py:321 — correctness — blocker (CONFIRMED)
**Scenario:** Dashboard left open; the last download finishes; the idle sleeper shuts aria2 down after `idle_timeout`. The status line says "reconnecting" forever; adds, retries and pauses fail until restart. `watch` skips every link with "connection refused".
**Fix:** On `Aria2Unreachable`, call `daemon.ensure_running` and swap in the new client.

### firelink/rpc.py:75 — correctness — blocker (CONFIRMED)
**Scenario:** A user with `http_proxy` set and no `no_proxy` entry for 127.0.0.1. `urlopen` sends the JSON-RPC call, token included, to the proxy; the daemon is reported unreachable.
**Fix:** Use an opener with an empty `ProxyHandler` for the local RPC.

### firelink/ytrun.py:241 — correctness — major (CONFIRMED)
**Scenario:** Pausing a YouTube download sends SIGTERM to yt-dlp only; its `aria2c -x16` child keeps downloading. Resume starts a second pair on the same files.
**Fix:** Start yt-dlp in its own session; stop it with `os.killpg`.

### firelink/ytqueue.py:123 — correctness — major (CONFIRMED)
**Scenario:** A supervisor's `hand_over` and the dashboard's 5 s fill both read `waiting()` before the lock; both claim job J and spawn two supervisors on the same files.
**Fix:** Inside the lock, refuse a job whose claim is already fresh.

### firelink/ytjob.py:47 — correctness — major (CONFIRMED)
**Scenario:** Pause written by the dashboard between the supervisor's read and write is overwritten with "active". Two writers share `<id>.json.writing`, so one `replace` can raise or install a truncated file.
**Fix:** Unique staging file per write; the supervisor re-reads and merges right before saving and keeps the dashboard's status.

### firelink/history.py:27 — correctness — major (CONFIRMED)
**Scenario:** Deleting a Completed row while a hook appends: the rename installs the old content and the new record is lost. Same for `started.prune`.
**Fix:** `fcntl.flock` on a sidecar lock around append and rewrite.

### firelink/instance.py:37 — correctness — major (CONFIRMED)
**Scenario:** Two starts together: B reads A's lock before A wrote its pid, sees 0, unlinks it and takes its own lock. Two dashboards run.
**Fix:** `fcntl.flock` held for the life of the process; the pid is information only.

### firelink/daemon.py:414 — correctness — major (PLAUSIBLE)
**Scenario:** After an idle shutdown `daemon.pid` stays; after a reboot the pid belongs to another program, which `ensure_running` SIGTERMs then SIGKILLs.
**Fix:** Only signal a pid whose command line is aria2c with our RPC port; clear the pid on idle shutdown.

### firelink/hook.py:148 — correctness — major (CONFIRMED)
**Scenario:** Category folder on an external volume: `Path.replace` raises EXDEV, the hook's catch-all logs it, and no history row, notification or on_complete happens.
**Fix:** `shutil.move`; a failed relocation keeps the original path and the record is still written.

### firelink/daemon.py:395 — correctness — major (PLAUSIBLE)
**Scenario:** Two `firelink --no-preview` after an idle shutdown both spawn aria2c; the loser's pid overwrites daemon.pid.
**Fix:** Hold `flock(state/daemon.lock)` across probe → spawn → wait.

### firelink/watch.py:153 — correctness — major (CONFIRMED)
**Scenario:** Dashboard open, `firelink watch`: `instance.holder(None)` raises TypeError, a traceback instead of the message.
**Fix:** Pass `where`.

### firelink/ytrun.py:190 — observability — major (CONFIRMED)
**Scenario:** `finalize` raises (cover fetch `IncompleteRead`, full disk): traceback to /dev/null, job later reaped as "stopped — nothing is downloading this" with the file on disk.
**Fix:** Catch in `main`, write the traceback to the job log and mark the job as error.

### firelink/ytrun.py:175 — architecture — major (CONFIRMED)
**Scenario:** Spotify/audio-only downloads are recorded as `video`; `on_complete` gets "video" as its category.
**Fix:** Category from `routing.resolve` on the landed file name.

### firelink/tui/ytadd.py:199 — architecture — major (CONFIRMED)
**Scenario:** A `[categories]` table without `video`: job dir becomes `.`, so videos land in whatever directory the supervisor inherited.
**Fix:** Fall back to `cfg.general.default_dir`.

### firelink/tui/app.py:556 — architecture — major (CONFIRMED)
**Scenario:** `firelink -d ~/iso -H 'Cookie: x' -c sha-256=… <url>` fails with 403; `r` retries into the category folder with no cookie and no checksum.
**Fix:** Copy `dir`, `header`, `checksum` from `get_option(gid)`.

### firelink/daemon.py:431 — observability — major (CONFIRMED)
**Scenario:** A slow start moves the queue to `session.bad` silently; a second failure overwrites the first `session.bad`.
**Fix:** Timestamped name and say so in the error.

### firelink/daemon.py:362 — observability — major (CONFIRMED)
**Scenario:** A config value aria2 rejects at startup is printed to spawn.log; the error shows unrelated lines from an old aria2.log.
**Fix:** Show spawn.log first.

### firelink/watch.py:51 — architecture — major (CONFIRMED)
**Scenario:** Copying an `open.spotify.com` link during `watch` sends it to the YouTube probe (yt-dlp's DRM extractor claims it).
**Fix:** Skip Spotify links in watch with a hint to run `firelink <url>`.

### firelink/tui/table.py:310 — performance — major (PLAUSIBLE, measured by the lens)
**Scenario:** 500 queued rows: ~234 ms per render at 12 renders/s; the UI lags and a core stays busy.
**Fix:** Re-render only when rows or cursor change; skip while hidden.

### firelink/ytqueue.py:215 — performance — major (CONFIRMED)
**Scenario:** 500 queued, all slots busy: one lock cycle per job each fill, ~0.4 s every 5 s.
**Fix:** Return early when no slot is free.

### tests/test_integration.py:252 — test-quality — major (CONFIRMED)
**Scenario:** The ytrun child gets `DL_STATE_DIR`/`XDG_CONFIG_HOME`, which firelink no longer reads, so it loads the developer's real config.
**Fix:** Give the child `HOME=tmp_path`.
